Diseño relacional y seguridad de credenciales.

PK id

Relación 1:N (Una carrera, muchos alumnos)

CREATE DATABASE universidad_db;
USE universidad_db;

-- Tabla Padre
CREATE TABLE carreras (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    duracion_semestres INT NOT NULL
);

-- Tabla Hija con Llave Foránea
CREATE TABLE alumnos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    carrera_id INT,
    FOREIGN KEY (carrera_id) REFERENCES carreras(id)
);

⚠️ Regla de Oro de Seguridad

Crea un archivo .gitignore y agrega .env y node_modules/. ¡Nunca subas tus contraseñas a GitHub!

Bonus: ORM vs SQL Puro

¿Deberías usar un ORM como Sequelize o seguir con SQL nativo? Analicemos los trade-offs.

Comparativa Técnica

🔵 SQL Puro (mysql2)

Ventaja: Máximo control y rendimiento. Sabes exactamente qué está pasando.
Desventaja: Escribir strings de SQL puede ser tedioso y propenso a errores manuales.

🟣 ORM (Sequelize)

Ventaja: Productividad. Trabajas con objetos JS (`Alumno.create()`), no SQL.
Desventaja: "Caja negra". Puede generar consultas lentas si no tienes cuidado.
