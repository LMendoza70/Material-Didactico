01 · Beneficios

Ventajas de usar el checklist

  • Refuerza la regla principal: nunca tocar la rama principal directamente.
  • Es interactivo y permite filtrar por roles (Propietario / Colaborador).
  • Proyecto sencillo pero real (C# Windows Forms) → ideal para principiantes.
  • Material didáctico coherente creado por ti.
02 · Configuración

Cómo proteger la rama principal (main)

1
Ve a tu repositorio → Settings
2
En el menú izquierdo selecciona Branches
3
Haz clic en Add branch protection rule
4
Configura la siguiente regla:
Opción Recomendado Por qué
Branch name pattern main Protege la rama principal
Require a pull request before merging ✅ Sí Impide pushes directos
Require approvals ✅ Sí (1 aprobación) Se necesita revisión
Dismiss stale pull request approvals ✅ Recomendado Revisa nuevamente si hay cambios
Include administrators ✅ Sí Tú tampoco puedas hacer push directo
03 · Flujo de trabajo

Flujo recomendado para estudiantes

  1. Tú (propietario) proteges la rama e invitas colaboradores.
  2. Estudiante hace fork o clona el repo.
  3. Crea su rama: git checkout -b feature/nombre-cambio
  4. Trabaja, hace commit y git push origin feature/nombre-cambio
  5. Abre un Pull Request hacia main
  6. Tú revisas, apruebas y haces merge.
