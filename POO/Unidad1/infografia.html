El Reto Lógico: El Dilema del Inventario

Imagina un sistema para una tienda de videojuegos. En el enfoque estructurado, crearías arreglos paralelos: nombres[], precios[], y stocks[]. El problema surge al escalar: si ordenas un arreglo, ¿cómo mantienes la sincronía? La POO resuelve esto agrupando los datos en una sola unidad: el Objeto.

El gráfico muestra cómo la probabilidad de pérdida de sincronía de datos crece exponencialmente en la programación estructurada frente a la estabilidad del encapsulamiento en POO.

🏗️ Clases, Objetos e Instanciamiento

La Clase es el plano arquitectónico; el Objeto es la casa construida en memoria. El proceso de crear un objeto a partir de una clase se llama Instanciamiento. Una sola clase puede generar infinitos objetos independientes.

🛡️ Encapsulamiento

Siguiendo Clean Code, nunca exponemos variables directamente. Usamos modificadores de acceso (private) y propiedades (public) para proteger la integridad de los datos.

Comparativa de errores de validación de datos: Acceso directo a campos vs Propiedades con validación lógica estricta.

🧬 Herencia

La Herencia permite crear una jerarquía donde una Clase Hija adquiere los miembros de una Clase Padre. Representa la relación "Es Un" y promueve una drástica reutilización de código.

Análisis de volumen de código: Las clases derivadas reutilizan la base, requiriendo solo líneas adicionales para su comportamiento específico.

🎭 Polimorfismo

El Polimorfismo es la capacidad de un objeto de comportarse de diferentes maneras. En C#, se logra sobrescribiendo métodos (override) definidos como virtual o abstract en la clase base.

Evaluación de comportamiento de la acción abstracta "EmitirSonido" implementada dinámicamente por distintas clases hijas.
