Sección 1

El Gran Problema: ¿Por qué no usar campos públicos?

El pilar de la Programación Orientada a Objetos (POO) llamado Encapsulamiento dicta que el estado interno de un objeto (sus variables o campos) debe estar protegido del acceso directo del exterior. Si permitimos que cualquiera modifique directamente los datos de un objeto, corremos el riesgo de romper la integridad de nuestra aplicación.

Ejemplo de código peligroso (sin encapsulamiento) 
public class CuentaBancaria
{
    // Campo público: ¡Muy peligroso!
    public decimal Saldo; 
}

// En el programa principal:
CuentaBancaria miCuenta = new CuentaBancaria();
miCuenta.Saldo = 5000; // Hasta aquí todo bien...
miCuenta.Saldo = -1000000; // ¡Grave! El saldo es negativo y nadie lo validó.

¿Qué falló aquí? Cualquiera puede alterar el saldo sin pasar por ninguna regla de negocio o autorización. El saldo de una cuenta real nunca debería admitir números negativos arbitrarios.

Sección 2

¿Qué es una Propiedad en C#?

Una propiedad es un miembro que proporciona un mecanismo flexible para leer, escribir o calcular el valor de un campo privado.

Perspectiva de Uso

Para quien consume el objeto, se ve y se comporta exactamente como un campo público con la sintaxis familiar del operador punto (objeto.Propiedad).

Perspectiva de Diseño

Para quien escribe la clase, es una pareja de métodos ocultos (get y set) idónea para inyectar validaciones y control.

Sección 3

Anatomía y Sintaxis de las Propiedades

C# provee múltiples sabores sintácticos según el nivel de control requerido.

Usa un campo de respaldo privado explicitamente para poder evaluar reglas antes de guardar.

C# Tradicional 
public class Persona
{
    private int _edad; // Campo de respaldo (Backing Field)

    public int Edad 
    {
        get { return _edad; }
        set 
        { 
            if (value >= 0 && value <= 120)
                _edad = value; 
            else
                throw new ArgumentOutOfRangeException("Edad inválida");
        }
    }
}

Cuando no necesitas código adicional en get/set. C# crea el campo privado ocultamente en memoria por ti.

C# Autoimplementada 
public class Producto
{
    // Limpio, rápido y seguro
    public string Nombre { get; set; }
    public decimal Precio { get; set; }
}

Ideal para campos que no deben mutar tras la construcción de la instancia.

C# Solo Lectura 
public class Cliente
{
    // Solo tiene get. Solo se puede asignar en el constructor.
    public string Rfc { get; } 

    public Cliente(string rfc)
    {
        Rfc = rfc; 
    }
}
Sección 4

Casos de Uso del Mundo Real

Caso 1: Validación Física

Impedir que un objeto adopte estados físicamente imposibles. Ejemplo: La temperatura no puede ser menor al cero absoluto ($-273.15$ °C).

if (value < -273.15) throw new ArgumentOutOfRangeException();

Caso 2: Datos Dinámicos / Calculados

No almacenes variables redundantes. Si puedes calcularlas a partir de otras, utiliza propiedades de expresión de flecha (=>).

public double Fahrenheit => Celsius * 9.0 / 5.0 + 32.0;

Sección 5

La Trampa de la Recursión Infinita

Este es el error número uno de los estudiantes en sus primeros exámenes. Consiste en llamar a la propiedad pública dentro de sus mismos bloques de acceso en lugar de utilizar el campo privado.

Código Incorrecto 
public string Nombre
{
    get { return Nombre; } // ¡Recursión!
    set { Nombre = value; } // ¡Recursión!
}

Esto produce StackOverflowException (Desbordamiento de Memoria).

Código Correcto 
private string _nombre; // Campo
public string Nombre
{
    get { return _nombre; } // Correcto
    set { _nombre = value; } // Correcto
}

Funciona perfectamente accediendo al campo de respaldo.
