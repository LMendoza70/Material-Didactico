👨‍💻 Flujo de Trabajo: Desarrolladores

Aprende el ciclo de vida de una funcionalidad (feature). Desde la clonación hasta el push de tu módulo específico.

1. Clonar y Ramificar

Obtén el código y crea tu propio espacio de trabajo aislado.

git clone [URL]
git checkout -b feature/login

2. Codificar y Commitear

Aplica principios de POO y guarda tus cambios frecuentemente.

git add .
git commit -m "feat: clase Auth"

3. Publicar Feature

Envía tu rama al servidor remoto para que otros la vean. 

git push -u origin feature/login

🔍 El Pull Request: Calidad de Código

El PR no es solo una entrega; es una conversación sobre la arquitectura y la calidad de tu código C#.

Lista de Revisión para el PR

¿Por qué revisar?

Aseguramos que el código sea mantenible. Revisamos:

  • Nombres de variables significativos.
  • Uso correcto de modificadores de acceso.
  • Ausencia de código redundante.
  • Manejo adecuado de excepciones.

⚡ Sincronización y Conflictos

🎨 Visual Studio: "Cambios de Git"

Guía visual para gestionar Git directamente desde el IDE sin escribir una sola línea de comando.

Panel de Cambios

El centro neurálgico de Git en Visual Studio (Ver > Cambios de Git).

1

Commit & Push: Escribe el mensaje y usa el botón "Confirmar todo e insertar".

2

Fetch/Pull: Usa las flechas en la esquina superior derecha del panel.

3

Ramas: Cambia de rama haciendo clic en el nombre actual abajo a la derecha.

🚀 Escenario Real: El Conflicto de la Clase Usuario

Veamos cómo Ana y Carlos, dos desarrolladores del equipo, enfrentan y resuelven un conflicto de Git mientras aplican conceptos de POO en C#.

1

El Contexto

La rama main tiene una clase Usuario.cs muy básica creada por el Líder.

public class Usuario
{
    public int Id { get; set; }
    public string Nombre { get; set; }
}
2

Trabajo en Paralelo (El problema)

Ambos desarrollan en sus propias ramas, pero modifican el mismo archivo y las mismas líneas.

Ana rama: feature/autenticacion

Añade encapsulamiento para la contraseña.

public class Usuario
{
    public int Id { get; set; }
    public string Nombre { get; set; }
    
    // Cambio de Ana
    private string _password;
    public void SetPassword(string pwd) { 
        _password = pwd; 
    }
}
Carlos rama: feature/roles-usuario

Añade un enum para los permisos.

public class Usuario
{
    public int Id { get; set; }
    public string Nombre { get; set; }
    
    // Cambio de Carlos
    public TipoRol Rol { get; set; }
    public enum TipoRol { Admin, Cliente }
}
3

La Colisión

Ana termina primero y hace su Pull Request. Se aprueba y su código entra a main.

Días después, Carlos intenta hacer Pull Request, pero GitHub le dice: "Can't automatically merge". Carlos debe resolver el conflicto localmente.

⚠️

Pasos de Carlos en Visual Studio:

  1. Va a la pestaña Cambios de Git.
  2. Hace clic en la flecha de Extraer (Pull) en main y luego intenta fusionar con su rama.
  3. Visual Studio muestra un aviso de Conflictos de combinación.
4

La Resolución (Visual Studio Merge Editor)

Carlos abre Usuario.cs. El IDE divide la pantalla. Carlos se da cuenta de que ambos códigos son necesarios (la contraseña de Ana y los roles de Carlos).

Resultado final seleccionado por Carlos:

public class Usuario
{
    public int Id { get; set; }
    public string Nombre { get; set; }
    
    /* --- CHECKBOX DE ANA MARCADO --- */
    private string _password;
    public void SetPassword(string pwd) { 
        _password = pwd; 
    }

    /* --- CHECKBOX DE CARLOS MARCADO --- */
    public TipoRol Rol { get; set; }
    public enum TipoRol { Admin, Cliente }
}

✓ Carlos hace clic en "Aceptar combinación", hace el Commit de resolución, y ahora puede subir su PR sin problemas. ¡La POO sigue intacta!
